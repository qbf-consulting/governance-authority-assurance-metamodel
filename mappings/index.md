# Mappings and Source Crosswalks

{% include gaam-meta.html %}


GAAM mapping documents are informative artifacts. They explain source provenance, architectural differentiation and potential semantic alignment without importing external conformance obligations into GAAM.

## Available crosswalks

- [Ecosystem Assessment Method](ecosystem-assessment-method.md)  
  Defines the bounded readiness vocabulary and schema v1.1 implementation-validation contract, including case roles, governance context, positive/negative semantics, evidence expectations and candidate tests.

- [EUDI Wallet ARF v3.0.0 GAAM Readiness Crosswalk](eudi-arf-v3.0.0-gaam-crosswalk.md)  
  Distributed-authority benchmark applying GAAM to federated regulatory authority, registry semantics, assurance composition, runtime governance and remedy boundaries.

- [vLEI EGF v4.0 GAAM Readiness Crosswalk](vlei-egf-v4.0-gaam-crosswalk.md)  
  Explicit-authority benchmark applying GAAM to delegation, organizational role authority, reliance semantics, assurance boundaries and revocation propagation.

- [EUDI and vLEI Comparative GAAM Takeaways](eudi-vlei-comparative-takeaways.md)  
  Extracts reusable implementation priorities and a test-oriented path from both assessments.

- [GAAM Source Adoption and Architectural Differentiation Crosswalk](tsmm-v0.22.0-adoption-crosswalk.md)  
  Documents how the ToIP Governance Metamodel Specification v1.0, its Companion Guide and TSMM v0.22.0 informed GAAM while preserving GAAM's independent normative boundary.

- [AI Governance Source-to-GAAM Crosswalk](ai-governance-source-to-gaam.md)  
  Tests AI-governance and agentic-AI concerns against GAAM v0.9.0 and distinguishes existing coverage, AI-profile constraints, external mappings and genuine core gaps.

## Interpretation rule

A mapping or source citation does not make an external specification normative for GAAM. Only requirements and artifacts designated normative within the GAAM repository establish GAAM conformance obligations.
