# v0.9.3 — Assurance Evidence and Publication Hardening

{% include gaam-meta.html %}

**Release date:** 3 November 2026
**Distribution / test-suite release:** v0.9.3
**Normative Candidate baseline:** v0.9.3
**Retained semantic and canonical artifact baseline:** v0.9.0
**Class:** Candidate maintenance / assurance tooling patch
**Normative change:** None

## Summary

v0.9.3 incorporates the bounded November 2026 adversarial-review engineering tranche. Its principal change is that GAAM now presents **more accurately bounded, reproducible and falsifiable repository validation evidence**. It does not claim that the entire normative model is executable or independently demonstrated.

## Corrections and capabilities

- **CLI and CI:** Reject misplaced `--pattern` filters rather than silently running the entire vector suite; align pilot probes, fix the broken pytest loader, install test dependencies and enforce regression tests.
- **Published documentation:** Repair links into Jekyll-excluded paths and enforce an excluded-link check. Improve landing navigation and connect the actual starter authority, receipt and claim artifacts.
- **Evidence interpretation:** Introduce a conservative 190-ID requirement-reference audit, distinguish test associations from requirement-specific verification and correct stale aggregate PASS wording.
- **Behavioural vectors:** Introduce optional `--suite v2` with five clocked, schema-valid raw-authority scenarios and expected reason codes; test that always-deny adapters do not pass the whole suite. Existing 46-vector v1 contract remains the default.
- **Experimental schemas:** Publish opt-in, separately versioned **informative** receipt, runtime, delegation and claim representations under `experimental/v0.10.0/`. Legacy v0.9.0 schemas, IDs, requirement semantics and profiles are unchanged. These fields are not promoted to normative conformance obligations.
- **Integrity claims:** Explicitly identify package integrity as checksum-only, not proof of source authenticity.
- **Generated evidence:** Validation and package reports are generated per commit/run and published via CI/Pages workflows, avoiding stale committed check totals. CI enforces clean-tree reproducibility.
- **Adoption and review:** Document identifier-resolution limitations, consequential-effect classification concerns, protocol mapping boundaries, three informative adoption configurations and a machine-readable disposition of all 29 review findings.

## Compatibility and migration

The v0.9.0 semantic baseline and frozen schema `$id` values remain authoritative, as incorporated by current v0.9.3. Existing v0.9.0 schema-valid artifacts remain valid under those retained identifiers. The default v1 vector adapter contract is unchanged. A script that previously passed `--pattern` *after* the adapter command must move it *before* the adapter; misordered invocations now fail instead of silently running all vectors. Consumers electing to use experimental v2 artifacts or experimental v0.10.0 schemas must explicitly opt in; no existing claims are automatically upgraded.

Distribution identity, conformance-kit manifest and portable result schema now identify v0.9.3, while semantic-version fields that expressly identify frozen GAAM v0.9.0 artifacts continue to use `0.9.0`. The release does not revise external implementations' prior evidence or make prior independent conformance claims.

## Assurance limits and residual findings

A green validation report establishes only the enumerated checks on that release commit. It is **not** certification, L4 independent assessment, complete requirement conformance, external interoperability, authenticated receipt origin or proven runtime enforcement. The existing v1 suite remains abstract and partly vulnerable to wrong-reason success. The new v2 suite covers five authority cases only, not the complete ten-case adversarial proposal. Missing per-requirement behavioural assertions, cryptographic authenticity, historic `$id` host reachability, delegated scope comparators, trustworthy freshness and consequential-effect classification remain openly dispositioned.

The [adversarial finding register](../docs/adversarial-review-disposition-2026-11.md) marks F-01–F-04 implemented at the repository-control level; other findings are partial or deferred. The existing v1.0.0 exit conditions, independent implementation requirements and normative change authority remain in force.

## Reproduction and provenance

The source of truth is the tagged repository state. Run:

```sh
python -m pip install -r requirements-dev.txt
python scripts/validate.py
python -m pytest tests -q
python scripts/check_excluded_links.py
python scripts/audit_traceability.py > /tmp/gaam-traceability-audit.json
python scripts/gaam.py run-vectors --suite v2 python conformance-kit/reference_adapter.py
python scripts/check_review_dispositions.py
```

The governed workflow waits for required validation on the exact publication commit, regenerates evidence, builds a reproducible distribution, and publishes release assets with the commit/tag identity. Consult the workflow artifact for run-specific evidence and the machine-readable release record for distribution digests.

Engineering history: [tracking issue #93](https://github.com/qbf-consulting/governance-authority-assurance-metamodel/issues/93), PRs #94–#100. This release is a bounded maintenance/evidence milestone, not closure of all adversarial-review findings.
