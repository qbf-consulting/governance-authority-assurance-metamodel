# v0.9.4 — Adopter Integrity and Gateway Evidence

**Release date:** 4 November 2026
**Distribution and portable test-suite release:** v0.9.4
**Normative Candidate maintenance baseline:** v0.9.4
**Frozen normative semantics, profiles and canonical identifiers:** v0.9.0
**Change class:** compatible Candidate maintenance and adopter/assurance tooling hardening
**Normative schema or semantic change:** **None**

## Why this release exists

This release consolidates the substantive adopter-facing changes since v0.9.3 into a coherent, reproducible distribution. It addresses package and evidence false-success risks, hardens portable adapter failure reporting, and provides a bounded delegated-agent gateway evaluation usable by implementers and reviewers. A green validation run means the documented checks passed **on that source revision**; it is not a new certification, trust-recognition or runtime authorization guarantee.

## Consumer-facing corrections

- **Package containment and integrity (PR #103):** reject absolute paths, traversal and symlink escapes; prevent missing declared checksums from being reported as passing. Integrity remains checksum-only, not provenance.
- **Portable runner failure semantics (PR #104):** bounded invocation timeout; machine-readable failure for malformed or non-object JSON, unavailable adapter, nonzero exit and stalled process.
- **Reader-facing baseline (PR #106):** correct the current Candidate/semantic baseline distinction.
- **Clean-room runtime and evidence boundary (PRs #107–#108):** test positive/negative v1 delegation and opt-in v2 raw-authority lifecycle plus an always-deny counterexample; reject missing/mismatched synthetic requirement evidence, duplicate references and escaped evidence paths.

## Adoption and assurance implementation

- **Bounded consequential gateway (PR #109):** explicit originating principal, acting agent, authority, delegated scope, local policy, requested purchase effect, evaluation clock, lifecycle/status observations, structured deny/indeterminate outcomes, attributable decision receipt and explicit `effectExecuted: false`.
- **Source-linked ten-element evaluation (PR #110):** map each required element to existing normative obligations and actual tests, with F-102-A–E findings preserved where evidence or interoperable semantics are missing.
- **Reader journeys and hand-off (PRs #111–#112):** three role-oriented navigation routes and externally reproducible instructions using a pinned source revision. This remains maintainer-authored guidance; accepted E2/E3 evidence is governed by issues #20 and #21.
- **Run-specific E1 dossier (PR #113):** CI executes the public gateway CLI across 16 declared cases and retains the exact inputs, expected/observed results, failure reasons, timestamps, source/tool versions, evaluation clock, policy context and disclosed limitations in the existing `gaam-validation-evidence` artifact. A synthetic local permit based on an unverified `source` label is exposed as an **assurance limitation**, never operational permission.

## Compatibility and migration

The v0.9.0 normative specification, canonical `$id` values, governed requirement/profile identifiers, JSON schema meanings and obligations remain unchanged. The portable result/kit metadata advances to v0.9.4; consumers comparing `releaseVersion` or `normativeVersion` in informative runner output should update their expectations to `0.9.4`. The existing v1 adapter input and Boolean output contract remains compatible. Optional v2 raw-authority vectors and experimental v0.10.0 schemas do not acquire normative status. No mandatory migration for canonical v0.9.0 artifacts.

The historical v0.9.0 schema-ID origin remains retained for compatibility; a mirror does not retroactively authenticate that host or a third-party issuer.

## Known limitations and residual risk

GAAM's current gateway evaluator and CI evidence are **synthetic, repository-controlled E1**. A structurally valid authority or decision receipt does not establish source/actor authenticity, valid governed acceptance, policy precedence, typed scope semantics for arbitrary policies, live revocation propagation, cryptographic receipts, replay prevention, a completed consequential effect or an independent implementation.

A fixed input digest demonstrates reproducibility, **not** trustworthy attribution. A source string can be changed while the local example still returns `permit`; this is deliberately exposed as an unverified trust boundary. Conflicting independent status observations are not adjudicated. Missing normative expression must be raised under governed Candidate change control, not filled using OAuth/MCP conventions or experimental fields.

The readiness state remains E1. This release neither establishes E2 evidence under #20, E3 interoperability under #21, L4 independent assurance nor eligibility to claim a production-enforcing gateway.
